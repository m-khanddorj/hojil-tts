# Direct speaker candidates with an actual-speech fitting gate

The preceding direct attention pilot stopped after update 2: development CER
rose from 2.0484% to 4.1899%, while the fixed token-loss constraint still passed.
Neither checkpoint met the custom-reference cosine target. This experiment
changes the trainable component and strengthens candidate selection with actual
matched training audio. It does not relax either final goal threshold.

## Native gradient evidence

A read-only probe replayed each of the first two fitting batches (16 recordings
each) through the existing speaker and attention adapters. All 36 fixed anchors
provided the pronunciation-loss gradients. No optimizer ran or weights changed.

| Fitting batch / policy | Speaker gradient cosine | Attention gradient cosine |
|---|---:|---:|
| Batch 1 / initial attention update 4 | +0.381447 | -0.176906 |
| Batch 2 / direct attention update 1 | +0.432349 | -0.196000 |

These are cosines between voice-loss and anchor-loss **parameter gradients**,
not generated-voice similarity. Positive values indicate locally compatible
descent directions under this parameterization. They do not establish speaker
causality by layer or predict audible generalization. Both posterior replays
were exact; attention gradients matched the actual earlier optimizer updates.
Original weights and both adapters remained unchanged. Two small-Qwen tests
verify joint gradient replay and the geometry calculation.

## Candidate construction

Initialization is the independently audited unfiltered attention update 4 with
the original speaker update 8. Only the existing rank-16 speaker-input adapter
(32,768 parameters) changes. Original acoustic weights, attention LoRA, codec and
speaker encoder stay fixed. No evaluation references or transcripts are fitted.

The verified first-batch voice gradient supplies a fresh AdamW proposal at
learning rate 0.003, zero weight decay and FP32 moments. The actual proposal is
projected if needed to preserve a common local voice/anchor descent direction.
Eight predefined scales, 1 through 1/128, are evaluated on the same 36 anchors.
Each feasible candidate must meet all of these conditions:

- Actual mean anchor NLL at most its original value plus 1e-6.
- Negative predicted voice-loss change using the actual rounded parameter delta.
- Maximum speaker-input change of 0.25% of the original vector norm, relative to
  initialization, across all 36 fitting speakers.
- The adapter's existing 5% total displacement bound.

Scales 1 and 1/2 failed. Scales 1/4 through 1/128 passed. The largest feasible
candidate (index 2, scale 1/4) reduced anchor NLL from 3.649726524 to 3.649717011,
with maximum speaker-input change 0.161054%. These are fitting diagnostics,
not speech-quality results. Original attention/acoustic weights were checked
throughout, and the in-memory starting speaker state was restored afterward.
Two actual small-Qwen optimizer tests verify candidate creation/restoration and
rejection of a mismatched cached anchor gradient.

## Actual-speech selection

Only the first four feasible candidates are eligible: indices 2, 3, 4 and 5,
in that fixed order. Each uses all 16 original fitting texts, references and seeds
on the same GPU FP32 generation path. All are independently ASR-scored, and voice
scores are recomputed against original references before selection.

The first passing candidate is selected using fitting data only. Requirements:

- Every recording terminates normally; no dropped cases or seed selection.
- Pooled character error rate does not increase.
- Mean original-reference cosine strictly increases.
- No recording loses more than 0.005 cosine or adds more than one character error.

Three tests verify strict joint improvement, rejection of damaged individual
clips despite an improving average, and complete matched condition coverage.
The search stops after the first fitting pass or four failed actual-speech trials.
No smaller scale is chosen from development/custom results.

Only a fitting-gate pass receives the complete unchanged 26-recording CPU FP32
screen. All generated audio, edit counts, voice scores, codes/EOS, source/model
identity and conditions are audited. A joint pass still requires all 114 existing
confirmation recordings with CER strictly below 3% and cosine strictly above
0.984 in both groups. There is no automatic promotion.

Before any candidate speech, all 16 unchanged GPU fitting recordings must
reproduce exactly. One CPU control must match the existing fully audited
26-recording baseline, whose complete parameter identity is reused. No earlier
GPU/BF16 evaluation is substituted for CPU evaluation.

## Status and artifacts

Native gradient analysis and candidate preparation are complete. The first
evaluation wrapper failed its unchanged-baseline control: it had omitted the
original explicit four CPU threads and disabled TF32 settings. All 16 WAV hashes
differed, and one duration changed. No candidate was evaluated or selected.
The failed run and its registered sources are preserved.

A separate v2 wrapper explicitly sets and registers those numerical settings,
and checks them on every phase. Both controls now pass: all 16 GPU fitting
waveforms and the CPU control reproduce exactly, with unchanged weights.
Actual fitting-speech selection is now complete. All three attempted candidates
passed independent waveform/condition/score/weight audits; the first two failed
the predeclared quality gate:

| Candidate | Fitting CER | Fitting WER | Fitting voice cosine | Gate |
|---|---:|---:|---:|---|
| Unchanged baseline | 4.4324% | 10.1351% | 0.9796891 | Reference |
| 2: scale 1/4 | 3.3514% | 7.4324% | 0.9780854 | Voice deterioration; up to 3 added character errors |
| 3: scale 1/8 | 3.4595% | 7.4324% | 0.9798011 | Up to 3 added character errors |
| 4: scale 1/16 | 2.9189% | 6.0811% | 0.9798626 | Pass |

Candidate 4 passed fitting selection. All 16 recordings terminated, none gained character
errors, and the worst per-recording cosine change was -0.00001073. Its maximum
speaker-input change on the 36 anchors is 0.039174%. Candidate 5 was not tried,
consistent with stopping at the first fitting-only pass. These fitting averages
must not be reported as validation results.

The complete 26-recording CPU screen subsequently passed its independent audit,
with zero cosine recomputation error and all weights unchanged during evaluation:

| Evaluation group | Initial CER → candidate CER | Initial WER → candidate WER | Initial cosine → candidate cosine |
|---|---:|---:|---:|
| Development | 2.0484% → 2.0484% | 4.5977% → 4.5977% | 0.9850573 → 0.9852271 |
| Custom reference | 1.6355% → 0.9346% | 4.6875% → 4.6875% | 0.9790958 → 0.9789036 |

The joint screen failed: custom-reference cosine remains below 0.984 and is
slightly worse than initialization. Both CER targets and development cosine
pass. No 114-recording expansion or promotion occurred. The original driver
completed normally with `joint_screen_failed`.

The custom mean hides mixed changes. Custom-004/seed-2026 gained 0.002792 cosine
and removed three character errors; custom-001/seed-2027 lost 0.004707 cosine
and added three errors. Custom-007/seed-2026 remained exactly unchanged at
0.964556 cosine. None of these evaluation examples is added to fitting.

This experiment improved fitting speech and development voice similarity but
did not transfer the voice gain to the requested reference. More shared-speaker
updates are not justified by these results alone. Reference-specific conditioning
trained on separate generated sentences is a possible next hypothesis, distinct
from the earlier failed reference-reconstruction CE objective; it has not been
implemented here. Any such experiment must preserve both evaluation groups,
the original reference scorer and the full confirmation requirement, and be
described as personalization rather than a universal-model improvement.
