# Reference-specific generated-speech adaptation

The shared speaker update improved development voice similarity but slightly
worsened the requested reference. The new hypothesis is a small conditioning
profile tied to that reference, with the shared model fixed. This is
personalization, not a claim that the universal model has improved. Both original
evaluation groups, their strict thresholds and all 114 confirmation recordings
remain required.

## Literature and methodological distinction

Beyond Fixed Targets studies per-speaker personalization of LLaSA-1B using
current-policy speech, including GRPO and self-distillation. Its reference-only
fixed-target SFT failure motivates avoiding reconstruction of the short reference
as the training target. Its English/ECAPA results do not establish Qwen/Mongolian
performance or calibrate our internal cosine threshold.
[Primary paper](https://arxiv.org/html/2610.17838).

VoiceTTA optimizes lightweight F5-TTS prefixes using generated-speech style,
speaker and intelligibility feedback. Its flow-matching loss proxy is not Qwen
token likelihood. The useful idea here is reference-specific generated feedback;
the proposed Qwen residual and its straight-through codec gradient are a different
experiment, not a reproduction of that loss or GRPO.
[Primary paper](https://arxiv.org/html/2606.26534).

## Isolated conditioning profile

Initialization is the audited attention-update-4/speaker-update-8 model. All
acoustic, attention-LoRA, shared-speaker-adapter, codec and speaker-encoder weights
stay frozen. A new 1,024-parameter residual is added after the shared speaker-input
adapter only when the caller supplies the exact registered reference-audio hash.
Other references use the unchanged shared adapter. Activation is scoped to one
call and restored even after exceptions; it does not infer a speaker identity
from an evaluation text or waveform.

The residual uses a smooth bound of 5% of the original input-vector norm. This
bound applies to the additional personal residual; the existing shared adapter
already has its own bound. Zero residual is numerically unchanged. The original
reference audio remains the scoring target, and the scorer is never adapted.

Three tests cover zero-output parity, unrelated-reference isolation with a
nonzero residual, nested/exception restoration, actual small-Qwen gradient replay
and finite differences, frozen original parameters and reference-identity checks.
The native CPU control reproduced all 26 original WAV hashes exactly: 20 inactive
development recordings and six active-but-zero custom recordings. All weights
were unchanged.

## New text partitions

Twelve unique texts are hash-selected from the existing preference-training text
pool before synthesis or inspection of their new scores. Every target transcript
and reference transcript in the full 114-recording confirmation panel is excluded
under the existing normalization. The first eight texts are for fitting; the
remaining four are reserved for personalization validation. Each uses seeds
41201 and 41202, producing 16 fitting and eight validation recordings.

All use the requested reference audio and its transcript as normal ICL
conditioning. This intentional use of the reference is explicit test-time
personalization. No ground-truth target-speaker recordings, evaluation target
transcripts, evaluation outputs or reserved validation texts enter gradients.
The original speakers associated with the unpaired texts supply text provenance
only; their voice recordings are not used as targets.

Collection uses CUDA FP32 talker/scorer and the CPU codec, with four CPU threads
and TF32 disabled. Reserved personalization validation must use this same backend
for paired comparisons. The final two-group evaluation remains CPU FP32 with its
unchanged seeds and sampling settings. Two text-partition tests verify exclusion,
uniqueness, deterministic ordering and failure when eligible data are insufficient.

## Verified local proposals

Only the 16 fitting trajectories supplied policy posteriors and codec gradients.
Three separate processes keep the native policy, frozen codec/scorer, and replay
within memory limits. Reference code probabilities stay constant. Exact native
hard-waveform forward values and posterior replay are checked. Allocated and
reserved GPU memory and per-recording time are recorded; unused allocator cache
is released between codec samples.

The planned local direction is the negative sum of normalized voice-loss and
token-NLL gradients. It provides common first-order descent unless the objectives
are exactly opposed. Actual anchor loss is still measured afterward. Four
candidate input displacements are predefined: 0.5%, 0.25%, 0.125% and 0.0625% of
the original vector norm. The inverse smooth-bound mapping sets those actual
input displacements rather than an arbitrary raw-parameter learning rate.

Two tests check common descent and exact displacement conversion; two more
prevent reserved validation records, missing/duplicate cases or truncated fitting
trajectories from entering optimization. The codec derivative is a biased local
surrogate. Fixed-hard-trajectory voice loss is not interpreted as a learning
curve or proof of better generated speech.

Candidate selection must use matched fitting speech with CER preserved and voice
improved, including the predeclared per-recording damage checks. Only the first
passing candidate may receive reserved validation and the complete unchanged
two-group screen. No evaluation transcript is used to choose a direction or scale.

## Current actual-speech evaluation

`reference_profile_evaluation.py` and its external sequential driver register
all four proposals before evaluation. They first reproduce all 24 GPU baseline
waveforms, then try candidates in the registered order. Only the first passing
16-recording fitting gate receives reserved-eight evaluation and the complete
26-recording CPU screen. Reserved results do not select another scale. The screen
also requires exact original waveform hashes for all 20 development recordings
whose references bypass the profile.

Two gate tests cover split contamination, matched coverage and per-clip damage;
one selection test prevents skipped trials, further fitting search after selection,
wrong-candidate validation and changed gate receipts. Both pronunciation and
voice metrics are independently recomputed for every evaluated candidate.

not a retroactive change to the active run or the final two-group thresholds.

## Prepared full confirmation

`reference_profile_confirmation.py` and its separate external driver implement
the original 114-recording panel for a passing mean-follow-up profile. They
refuse preparation until the screen process is complete and its independently
audited 26 recordings pass the strict thresholds in both groups. Confirmation
pins that evidence and the original panel, preserves all extra case metadata,
uses CPU FP32 generation, and checks exact waveform reproduction of all 26
screening conditions. GPU ASR and the independent CPU speaker audit run in
separate processes. All 114 recordings, original references and both fixed seeds
remain mandatory. No fitting, scale search or automatic model promotion occurs.

Three focused tests passed for actual strict screening thresholds in both groups,
complete 88+26 coverage, truncation, changed scope, missing/duplicate conditions,
screening waveform parity and additional case metadata. This confirms the guard
logic, not native 114-recording execution. The runner has not been registered or
launched because the completed screen failed the joint requirements.

The separate mean-objective evaluation is complete and failed. No candidate has been promoted or passed
the joint goal. The full registered 114-recording confirmation remains mandatory
if the screen passes. Artifacts remain outside Git under
`reference-profile-collection`, `reference-profile-proposals`, and
`reference-profile-evaluation`, and `reference-profile-mean-evaluation`.
Registered historical sources remain unchanged.
