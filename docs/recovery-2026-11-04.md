## Restore

1. For inference, follow [the playground guide](playground.md), using the verified
   local export or the pinned Hugging Face download and a local reference profile.
2. For training recovery, preserve `COMPLETE.json`, `weights.pt` and `training.pt`
   together. Verify their sizes and SHA256 values before loading them.
3. Restore the prepared dataset, saved cohort/split manifests, original training
   implementation and `train.json`/checkpoint configuration into external paths.
   Recreate the recorded dependencies and base-model revision. Path changes must
   be explicit; do not launch an old driver or reuse historical process IDs.
4. Rebuild generated token/features cache from the verified dataset and pinned
   model/source when needed. The bulk cache is reproducible intermediate data,
   not an additional trained checkpoint; its provenance manifest is backed up.
   Validate cache contracts/fingerprints and checkpoint compatibility before a
   resumed training run. Exact resumed GPU trajectories are not guaranteed across
   different hardware/software.
5. Use a newly configured, bounded run only after checking the saved experiment
   authorization and validation evidence. Recovery does not change failed pilot
   quality evidence into a passing quality claim.

## Billing and retention

All project GPU pods were stopped before this scoring pass; start attempts failed
for lack of capacity, and scoring ran locally. Do not treat a stopped pod or a
network volume as a backup guarantee. Runpod says network storage continues to
bill and may eventually be terminated if its charges cannot be covered at zero
balance. Deleted data cannot be recovered. See [Runpod billing documentation](https://docs.runpod.io/accounts-billing/billing).

No pods or network volumes were deleted, no billing settings changed, and no new
GPU was rented for this evaluation. Retention beyond the scope above should be
backed up before intentionally letting the account balance lapse.
