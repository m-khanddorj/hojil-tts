# Qwen3-TTS 0.6B training audit — November 9, 2026

Follow-up: [the fresh FP32 epoch and observability report](0.6b-fresh-fp32.md)
records the completed full-epoch experiment and two-seed speech comparison.
The FP32 continuation remains the selected model.

The 0.6B run was **LoRA adaptation**, not full-parameter fine-tuning. “Full” in
`qwen06-cv27-full` meant the full retained training cohort. It froze the base
talker and trained 12,009,472 rank-16 adapter parameters in the talker decoder,
residual-code decoder and text projection. Merging adapters for inference does
not change how the model was trained. The README's older full talker run is **1.7B**.

## Quality evidence

Pooled ASR rates, punctuation ignored, use the same 44 unseen validation clips
from ten speakers and the same generation seed. They are development recognizer
proxies, not human intelligibility or naturalness ratings.

| Model | CER | WER |
| --- | ---: | ---: |
| Untuned base | 24.45% | 56.39% |
| One-epoch LoRA | 7.24% | 15.53% |
| Historical BF16 continuation, 176 updates | 8.30% | 17.12% |
| New FP32 continuation, selected update 88 | **5.65%** | **13.24%** |

The continuation's WER increased by 1.60 percentage points; its speaker-cluster
bootstrap interval is -4.15 to +8.23 points. This does not establish that further
training generally hurts, but it gives no reason to deploy that continuation.

The new bounded experiment completed 176 updates and selected update 88 using
the preset 0.002 improvement threshold. Against epoch one, CER decreased by
1.59 percentage points (21.95% relative), and WER by 2.28 points (14.71% relative).
Its WER speaker-bootstrap interval is **-5.95 to +1.17 points**: the point estimate
improved, but ten speakers and one generation seed do not establish a general
improvement. This candidate is not yet listener-validated, and the reserved test
cohorts remain untouched. It combines the precision and batching changes with
additional training; this is not an isolated causal estimate of FP32's benefit.

Peak reserved training memory was **6.06 GiB**, versus **6.50 GiB** in the
historical 176-update continuation. The last update timer was 363.36 seconds
(including intervening validation/checkpoint work, excluding setup/final
validation), versus 395.67 seconds historically. These are observed laptop runs,
not repeated controlled speed benchmarks. All 466 adapter tensors and Adam
moment buffers were verified FP32 in the saved checkpoint. Fewer than 0.001%
of adapter elements stayed unchanged in the selected checkpoint.

The historical teacher-forcing diagnostic measured combined losses of 3.335 on
91 duration-matched training clips, 3.351 on 91 familiar held-out clips, and
3.410 on 44 unseen clips. The small matched gap does **not** show strong
overfitting or prove underfitting. Codec loss and sampled speech errors differ.

## Implemented changes

1. **FP32 updates.** All 466 adapter tensors and both Adam moment buffers were
   BF16. Low-level PEFT injection did not promote them. After the historical
   176-update continuation, 93.55% of LoRA A elements and 49.77% of LoRA B elements
   stayed bit-identical. This is consistent with rounded-away updates; it does
   not prove the cause of a speech error. Cast trainable parameters to FP32
   before creating/restoring Adam and assert FP32 moments. Keep the frozen base
   and forward autocast BF16. This follows
   [PEFT's adapter precision guidance](https://huggingface.co/docs/peft/developer_guides/troubleshooting#selecting-the-dtype-of-the-adapter).
2. **Validation selection.** Use a fixed 135-clip development set: all 44 unseen
   clips and one deterministic clip per 91 eligible familiar speakers. Average
   cohort losses equally. Preserve best weights separately from latest resume
   state, allow the starting model to win, and apply early stopping. Selection
   requires a configured minimum loss improvement (0.002 in this experiment),
   so a marginally lower loss need not replace the selected checkpoint.
   Generated speech still decides deployment.
3. **Less wasted memory.** Project only supervised target/EOS hidden states into
   codec logits. Context/padding logits contributed no loss. Tests verify
   equivalent losses and gradients. Budget both target frames and full padded
   sequence length, including reference audio/transcripts. Persist smaller OOM
   budgets rather than repeating the same failed size each update.
4. **Fix the tiny tail.** The original final update contained one clip and had
   gradient norm 6.1875. Fold a tiny remainder into its preceding update: one pass
   now has 1,750 updates and 17 clips in the last group. Preserve token-weighted
   normalization including EOS, rather than averaging microbatch means.
5. **Reproducibility.** Cache transcripts; fingerprint feature shards, source,
   base weights and validation selection; check target/reference text/audio/split
   leakage; save optimizer and RNG state. Retry OOM only during forward/backward,
   never after a potentially partially applied optimizer step.

## Next experiments

- Validate FP32 with the same rank, cohort and schedule first. Continuation
  cannot recover precision lost during the original epoch. A fresh FP32 epoch
  is a separate comparison, supplied as `configs/qwen06-lora.json`.
- Test tempered/capped speaker sampling: ten speakers provide **48.33%** of clips;
  the median speaker has five. Blind speaker equalization would repeatedly
  oversample tiny/noisy speakers, so do not enable it without an ablation.
- Compare mixed conditioning with non-streaming-only training if deployment
  remains non-streaming. Evaluate multiple seeds with fixed references.
- Then test ranks or broader coverage. There is no evidence yet that rank 16,
  another rank, or full talker tuning is best. Reserve test cohorts until the
  recipe and decoding policy are frozen.

## Reproduce

Use explicit paths outside Git and an already downloaded pinned model. The core
package stays dependency-free; the training environment needs the recorded
Torch/CUDA, Qwen, Transformers and PEFT versions, plus SoundFile, NumPy,
torchaudio and safetensors. No command downloads models or provisions compute.
The package pins are also recorded in `requirements-training.txt`.
On restricted Windows environments set `TEMP`, `TMP` and `NUMBA_CACHE_DIR` to
writable external directories.

```powershell
python -m scripts.audit_qwen06 --run <epoch-one-run> --continuation <old-continuation> --cohort <backup>/cohorts/train.jsonl --output <external>/audit.json

# Bounded continuation using the recovered optimizer:
python -m training.engine --base <pinned-base> --backup <backup> --features <epoch-one-run>/features --init-checkpoint <epoch-one-run>/resume.pt --output <new-external-run> --config configs/qwen06-lora-continuation.json

# Fresh FP32 epoch, without a parent checkpoint:
python -m training.engine --base <pinned-base> --backup <backup> --features <epoch-one-run>/features --output <another-new-run> --config configs/qwen06-lora.json

# Add --resume to the identical invocation after interruption.
# Export selected weights and compare all 44 generated validation recordings:
python -m training.evaluate --base <pinned-base> --run <new-external-run> --epoch-one <epoch-one-run> --backup <backup> --asr <pinned-buzzasr>
```

`best.json` points to the adapter selected by held-out codec loss; `resume.pt` is the latest
optimizer state. They can represent different updates. Inference uses the
historical BF16 merge policy for a comparable speech evaluation; FP32 master
adapters remain available. Lower codec loss alone never promotes a model into
the playground or Hugging Face.

The full talker configuration is an optional, unrun alternative. It would train
905,788,672 parameters and requires more VRAM. The user selected LoRA as the
current priority. No Runpod GPU was started during this audit.

Verification: 76 repository tests passed, followed by three additional paired
evaluation/pooled-scoring tests. Tests include actual small Qwen architectures,
generation-prefix alignment, next-frame labels, batch-partition gradient parity,
FP32 optimizer restoration, split/reference leakage and score denominators.
