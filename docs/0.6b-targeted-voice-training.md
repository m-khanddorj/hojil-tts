# Targeted text-adapter training with voice checks

Authorized November 10, 2026: keep the user-preferred halfway voice, improve
pronunciation, and evaluate both at every checkpoint. This is a bounded pilot,
not a promise that freezing weights alone preserves perceived voice.

## Starting model and trainable scope

Reconstruct the exact FP32 halfway weights from the pinned original base and
epoch-2 merged model: `W = 0.5 * W_base + 0.5 * W_epoch2`. Do not round this
blend to BF16. Freeze the complete model, including the main decoder, residual
predictor, embeddings, speaker encoder and codec. Inject a new rank-16 LoRA
only into the two text-projection matrices, with alpha 16 and dropout 0.05.
Only four tensors (A/B for each projection), totaling **114,688 parameters**,
may train. Zero-initialized B makes
the new adapter initially a no-op. The prior adapter optimizer is not reused;
these are fresh parameters with fresh FP32 AdamW state.

Keep frozen storage and trainable parameters in FP32. Training forward/backward
uses BF16 autocast with gradient checkpointing; generation uses CPU FP32, the
same backend as the accepted halfway voice. Before the first training update,
the initial custom example 001 at seed 2026 must reproduce the accepted WAV
SHA-256 exactly. Hash every frozen parameter before and after each training
checkpoint. An unexpected trainable tensor, changed frozen parameter or
baseline mismatch stops the run.

## Registered pilot

Configuration: `configs/qwen06-text-voice-pilot.json`.
Entrypoint: `python -m training.targeted_voice --config CONFIG_PATH`.
All directory arguments in that configuration identify existing local inputs;
there are no downloads, cloud resources or remote writes.

- Maximum 88 updates, 16 clips per update: 1,408 clips, about 5% of the existing
  28,001-clip training cohort. Deterministic shuffle uses seed 2026 plus epoch 2.
- Checkpoints at steps 0, 22, 44, 66 and 88. Each nonzero checkpoint is evaluated
  before another training segment starts.
- AdamW, weight decay 0.01, peak learning rate 5e-5, final rate 1e-5, eight-update
  warmup, gradient clipping at 1.0. FP32 parameters and optimizer moments.
- Use same-speaker reference audio/text on every training clip, with the
  non-streaming sequence layout used for this voice-cloning request. The
  objective remains first-codebook CE plus 0.3 times residual-codebook CE.
- A short pilot can remain underfit. Failure to improve in 88 updates is not
  evidence that text-only adaptation can never work.

## Evaluation after every checkpoint

Select one prompt per each of the ten unseen **development** speakers using a
fixed hash of seed and ID, without consulting scores. Add the three existing
custom-reference sentences. Generate all 13 prompts at both seeds 2026 and
2027: **26 recordings per checkpoint**, all retained. This is a small screening
panel; a promising candidate needs broader development confirmation before a
general quality claim. The already inspected reserved test is not used.

Use the pinned BuzzASR model, deterministic ASR decoding and existing text
normalization for CER/WER. Measure speaker cosine with the frozen original
Qwen encoder, report speaker-weighted means separately for development and
the custom voice, and preserve every recording's score and hash. This internal
encoder is not independent perceptual validation.

Also evaluate teacher-forced loss on ten familiar and ten unseen validation
clips, plus ten training clips matched to the familiar speakers and codec
lengths. Log gradient norms, learning rate, update time, GPU memory, OOM retries
and frozen-weight verification. The listening dashboard shows these losses
alongside pronunciation and voice scores.

## Conservative screening and stopping

The unmodified halfway baseline remains eligible to win. A checkpoint is only
a listening candidate if it has lower pooled development WER, no pooled CER
increase or seedwise WER increase in either evaluation group, and no decrease
in either group's mean speaker cosine. A recording losing more than 0.005
cosine also rejects it. That last threshold is a conservative engineering
review flag, not a calibrated perceptual boundary.

Two consecutive voice-screen failures stop this pilot early. Otherwise the
88-update budget ends it. Accuracy improvements cannot override voice failures.
The global model-selection pointer is never changed automatically. Any
eligible checkpoint still needs listening and broader development evaluation.
