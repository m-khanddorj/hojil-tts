The evidence is `masked-native-replay-diagnosis-v1.json` outside Git.

PyTorch documents that mathematically equivalent batched and sliced operations
need not be bitwise identical in [its numerical accuracy guidance](https://docs.pytorch.org/docs/main/notes/numerical_accuracy.html).
The v1 execution and failure remain immutable. The separate v2 registration
uses fixed raw-logit and probability-sensitive bounds, multiple fitting-only
length-frontier probes, both reference modes, and zero/nonzero adapters before
any fitting. These checks do not change the speech-quality goals or panels.

The v2 numerical limits, fixed before new production controls, are maximum
absolute logit error `5e-4`, mean absolute logit error `5e-5`, maximum
all-vocabulary log-probability error `5e-4`, maximum target-token
log-probability error `2e-4`, and maximum KL in either direction `1e-8`.
If the winning token changes near a numerical tie, each distribution's
cross-winner log-probability regret must be at most `2e-4`. Comparisons use
float64 probability calculations from FP32 model logits, with each main or
residual branch checked separately. These are local engineering limits,
not limits prescribed by PyTorch. Eleven small tests check numerical ties,
localized corruption, head/frame permutation, rare target/non-target tokens,
invalid inputs, and serialized metric guards.

## Why this experiment

The new hypothesis is ordinary supervision on real, distinct, same-speaker
reference/target recordings, while a fresh decoder adapter has no direct effect
on reference/control rows. This differs from the failed generated-preference
pilots and their chosen-output likelihood anchor. In particular,
[the calibrated preference pilot](0.6b-calibrated-quality-preferences.md) used
DPO plus five times generated chosen-output NLL, not this real paired objective.

[The earlier reference-protected pilot](0.6b-reference-protected-training.md)
trained target-text projections on a halfway backbone and improved some CER
scores, but custom voice cosine fell to 0.98374. Therefore unchanged direct
reference computations are an architectural constraint, not a guarantee that
output voice is preserved. Generated pronunciation and voice remain the
selection criteria. The failed
[direct voice pilot](0.6b-direct-voice-pilot.md) also shows why a small teacher
loss change alone cannot establish speech safety.

## Shared inference and teacher-forcing policy

Use full ICL, one example at a time, Auto language and nonstreaming generation.
Let `P` be the native prefix length, `nr` and `nt` the sliced reference and
target text lengths, `a=8+nr`, and `b=a+nt`. Fresh Q/V LoRA is active only at
target-text decoder rows `[a,b)` and teacher/generated rows `>=P`.

In full-reference mode, protected prefix rows retain the frozen full policy.
In half-reference mode, they use the immutable halfway acoustic matrices and
bypass an existing outer LoRA. Target-text and generated rows use the frozen
full policy plus the new adapter in both modes. Text projections stay frozen:
half reference/control and full target in half-reference mode, full everywhere
in full-reference mode. Native prefix PAD stays half in the half branch, but
the recurrent generated-frame PAD is full in both branches. Both generation
PAD arguments must follow this rule; teacher suffix construction must use a
separate full PAD rather than blindly reuse the prefix PAD.

During deployment, only the pinned custom reference WAV SHA selects the half
branch; development references select the full branch. During fitting, each
real same-speaker pair is replayed in both modes, so the half branch is trained
without inventing custom-reference labels. This explicit training augmentation
does not broaden the deployment dispatch rule.

Reference/control parameters are frozen and receive no direct fresh adapter
residual. Do not detach their hidden states or KV tensors: later reference
codec rows can attend target-text states, and target gradients must flow through
those frozen operations. Use full-sequence `use_cache=False` teacher forcing,
with immutable routing scope retained through backward and gradient-checkpoint
recomputation. Reusing a prefix cache across optimizer updates is prohibited.
The state at `P-1` predicts target frame zero; residual codebooks use that same
pre-frame state. The final consumed real frame predicts EOS.

## Bounded fit

Train fresh additive rank-4 Q/V adapters on main decoder layers 10–17 only.
Keep old LoRA, speaker adapter if present, all original acoustic/text weights,
embeddings, heads, residual predictor, codec, speaker encoder and halfway
alternatives frozen. Use FP32 parameters, forward and optimizer state, no
autocast, dropout zero, AdamW with constant learning rate `2e-5`, weight decay
zero, gradient norm clipping at 1, and a fresh optimizer. These are bounded
engineering choices, not a claim of optimal hyperparameters.

Run at most 32 updates with checkpoints 0, 8, 16 and 32. Seed the new adapter
and data ordering with 20261111. Build a deterministic shuffled cycle of the
47 speakers and within-speaker row queues; take eight distinct speakers per
update, one real pair each. Continue the same 47-speaker cycle across updates;
eight consecutive positions cannot repeat a speaker, including at the cycle
boundary. Replay each selected pair in both
modes, alternating their execution order by update parity. This yields 16
sequence examples per update with equal speaker/pair and mode weights.
Accumulation may use microbatch one. Do not shorten an utterance to fit memory;
resolve memory limits before protocol registration.

For each clip and mode, optimize:

`mean(main-codebook CE, including real EOS) + 0.3 * mean(residual-codebook CE)`.

The residual mean covers all 15 residual groups on real target frames and has
no invented residual EOS. Average the two mode losses, then average the eight
pair losses. This normalization gives each sampled speaker/pair equal weight
instead of letting long utterances dominate. Log pooled token-weighted losses
as additional diagnostics, but do not silently substitute them for the fitting
objective. There is no DPO term or generated chosen-output anchor in this pilot.
