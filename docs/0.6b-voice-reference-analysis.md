# Reference voice investigation

On November 10, 2026 the user reported that the custom-reference samples did
not sound like the supplied voice. This report separates pronunciation scores
from speaker identity. No human listening score has been collected, and no
checkpoint was promoted by this investigation.

## What was checked

The generation used the exact requested 3.8-second WAV, SHA-256
`860372aef1859fa8295d68a16a20fa0b0f9bad2e19b30048da0ee1039b32827d`, with
the matching transcript, `Энэ өдрийг тэрээр тэсэн ядан хүлээжээ.`
Full conditioning supplied both the reference audio tokens and speaker
embedding. The reference was not replaced by a preset speaker.

The original base model and merged epoch-2 model have identical values for
all 76 speaker-encoder tensors. Their reference embeddings are exactly equal.
This establishes that the input speaker encoder was preserved; it does not
establish that the adapted speech decoder preserved the perceived voice.

Training optimized first-codebook cross entropy plus 0.3 times residual
codebook cross entropy. Speaker conditioning was present, but there was no
explicit speaker-similarity objective. Checkpoint comparisons measured codec
loss and ASR CER/WER without measuring speaker similarity. Consequently,
better word accuracy could conceal voice drift. This is a plausible mechanism,
not a proven attribution of the user's observation to LoRA.

## Controlled comparison

Use the first of the three already requested example texts, seed 2026,
CPU FP32 inference, the same decoding settings and exact reference. Compare
the original base model and epoch 2 with full reference conditioning and
speaker-embedding-only conditioning. Reuse the original epoch-2 full-reference
recording rather than regenerate or select a favorable output.

| Model and conditioning | Internal speaker cosine | Duration |
| --- | ---: | ---: |
| Base, full reference | 0.98616 | 4.32 s |
| Base, embedding only | 0.97999 | 4.80 s |
| Epoch 2, full reference | 0.97293 | 4.72 s |
| Epoch 2, embedding only | 0.97634 | 3.68 s |

The full-reference comparison is consistent with some voice drift after
adaptation. One text and one seed cannot establish its extent or cause.
Embedding-only conditioning slightly increases the epoch-2 cosine but is not
a demonstrated perceptual or pronunciation improvement. It is not adopted as
a new default.

These are cosine values from Qwen's own speaker encoder, not percentages or
an independent speaker-verification system. Natural same-speaker controls
(one target/reference pair per test speaker, ten pairs) average 0.98653,
range 0.97522–0.99369. The 90 cross-speaker controls average 0.93864,
range 0.88263–0.96687. The supplied custom reference versus ten other natural
speaker references averages 0.93917. The controls suggest the encoder carries
speaker information, but do not define an acceptance threshold or overrule
the user's listening judgment. Pairs sharing speakers are not independent.

Reference length alone is not an established cause: the
[official model card](https://huggingface.co/Qwen/Qwen3-TTS-12Hz-0.6B-Base)
advertises cloning from three seconds. A longer clean reference may still be
worth a controlled comparison. Full versus embedding-only prompt behavior is
specified in the [official inference source](https://github.com/QwenLM/Qwen3-TTS/blob/main/qwen_tts/inference/qwen3_tts_model.py).

## Reusable diagnostic

`python -m training.speaker_diagnostics --base ORIGINAL_BASE --run EPOCH_RUN
--backup RECOVERY_ROOT --seeds 2026 2027` measures existing verified development
recordings on CPU, without resynthesis. Supply local absolute paths for the
three directory arguments. The output is `speaker-diagnostics.json` inside
the external run directory. Test mode requires explicit `--cohort unseen-test`
and writes `speaker-test-diagnostics.json`, keeping the cohorts separate.

The report includes recording-weighted and speaker-weighted cosine, per-seed
and per-speaker values, every recording's audio/reference hashes, encoder and
generation model hashes, plan hashes and the diagnostic source hash. It does
not change checkpoint selection. Missing or invalid audio/embeddings fail
rather than silently dropping a recording.

Three focused tests cover speaker weighting, duplicate recording rejection,
and invalid measurements. An end-to-end CPU run on all 88 epoch-2 development
recordings reproduced the independent artifact-script results exactly.

## User listening feedback and controlled interpolation

On November 10 the user judged the **original base model closer to the reference**
than epoch 2, explicitly ignoring pronunciation errors. This was an unblinded
comparison of example 001, not a numerical rating or a multi-speaker listening
study. It strengthens the voice-drift hypothesis for this reference and agrees
with the direction of the internal cosine diagnostic.

Register one halfway blend before generating it: FP32 interpolation
`W = 0.5 * W_base + 0.5 * W_epoch2_merged`, preserving the reference encoder.
Because the merged endpoint was stored in BF16, this is a weight-interpolation
experiment rather than mathematically exact rescaling of the original unmerged
LoRA adapter. Compare scales 0, 0.5 and 1 on all three previously requested texts,
the same reference, seed 2026 and unchanged decoding settings. Reuse the existing
endpoint recordings where available; generate only the missing base examples
and the three halfway samples. Retain every output, with no favorable retries.

Score all nine recordings with the pinned BuzzASR configuration and the fixed
base speaker encoder. Keep these custom-reference results separate from the
development/test benchmark. This experiment neither starts new training nor
changes checkpoint selection. Perceived improvement still requires listening.
Protocol, audio, hashes and results live in the external `reference-half-blend/`
directory under the artifact root above.

The registered interpolation experiment completed and all nine audio hashes
and listening-page links were verified. On these three custom-reference texts:

| Variant | CER | WER | Mean internal speaker cosine |
| --- | ---: | ---: | ---: |
| Original base | 12.15% | 50.00% | 0.98560 |
| Halfway blend | 5.61% | 18.75% | 0.98394 |
| Full epoch 2 | 2.80% | 6.25% | 0.96825 |

The halfway blend recovered much of the internal speaker similarity but
introduced more word errors than full epoch 2. This is a measured tradeoff,
not a proven improvement or a selected replacement. The sample contains only
32 reference words across three texts, one voice and one seed. All 233 changed
weight tensors were in the talker; the speaker encoder was unchanged. The user
subsequently confirmed: **"voice is closer but pronunciation is worse."** This
is an unblinded qualitative judgment, consistent with the measured tradeoff.

## Pronunciation with the halfway weights fixed

In response to the request to improve pronunciation without losing the voice,
register one decoding experiment: lower the main sampling temperature from
0.9 to 0.6. Keep the halfway model weights, exact reference audio/text,
non-streaming conditioning, target texts, residual-predictor settings and all
other generation parameters fixed. Qwen's [inference source](https://github.com/QwenLM/Qwen3-TTS/blob/main/qwen_tts/inference/qwen3_tts_model.py)
exposes separate main and residual-predictor sampling settings. A lower main
temperature is a hypothesis to test, not an established pronunciation fix.

Compare both settings on all three texts at seeds 2026 and 2027. Reuse the
three verified existing baseline recordings at seed 2026; generate the other
nine once. Retain every output. Report pooled and seedwise CER/WER, mean
internal speaker cosine and every paired change. A lower error rate without
a lower mean cosine is only a screening result; retaining the perceived voice
still requires listening. No new checkpoint is trained or promoted by this
experiment. Artifacts live under `half-blend-pronunciation/` outside Git.

The decoding experiment failed the pronunciation criterion: pooled CER rose
from 7.24% to 10.98%, and WER from 23.44% to 31.25% (15 versus 20 word errors
out of 64). Both seeds worsened. Mean internal speaker cosine was similar,
0.98496 versus 0.98527. Retain this negative result; do not adopt temperature
0.6 as a pronunciation improvement.

Register a second, distinct ablation after that result: return generation to
temperature 0.9 and restore only `talker.text_projection.linear_fc1.weight`
and `linear_fc2.weight` to their full epoch-2 values. Keep every other adapted
matrix at the halfway blend, with the original speaker encoder and codec.
This tests whether stronger learned text conditioning can help pronunciation
without the full-model voice regression. Text projection is not assumed to
affect pronunciation exclusively; voice still requires measurement and listening.
Use the same three texts and two seeds, reuse all six verified baseline
recordings, and generate each candidate once. Artifacts and the registered
protocol live under `half-blend-text-mapping/` outside Git.

The text-mapping ablation reduced pooled CER from 7.24% to 5.14% and WER
from 23.44% to 17.19% (15 to 11 word errors), but did not meet the joint
screening criterion. Mean internal cosine fell from 0.98496 to 0.98421;
seed 2026 WER worsened from 18.75% to 21.88%, while seed 2027 improved from
28.13% to 12.50%. Example 007 at seed 2027 lost 0.00868 cosine. This is an
inconsistent tradeoff rather than demonstrated pronunciation improvement with
preserved voice. No candidate is promoted on these averages.

Register one final component ablation for this round: use the full epoch-2
values for the main decoder and text projection (198 adapted matrices), while
restoring the original residual code predictor (35 adapted matrices). Keep
the original speaker encoder and codec. This tests whether the residual
predictor contributes to the voice regression; it does not assume that the
components perfectly separate content and identity. Keep all three texts,
both seeds and the original temperature-0.9 decoding. Reuse the same six
halfway baseline recordings, generate six candidates once, and retain all
outputs. Artifacts live under `main-only-adaptation/` outside Git.

The final component ablation also failed the joint criterion. Pooled CER was
5.37% and WER 15.63% (10/64 word errors), but mean internal speaker cosine
fell substantially to 0.97365 from the halfway baseline's 0.98496. Seed 2026
WER worsened to 21.88%; seed 2027 improved to 9.38%. Returning the residual
predictor to its original weights did not remove voice drift under full
main-decoder adaptation. This is evidence about this small diagnostic, not a
proof that a particular component exclusively controls speaker identity.

All three experiments completed. Their protocol source hashes, 24 unique
recordings, finite waveforms and listening-page audio links were verified;
21 recordings were new in this round. No setting met the joint criterion or
was promoted. The external `voice-pronunciation-round.html` summarizes the
complete results, including negative trials.

The next proposed training experiment is to freeze the user-preferred halfway
speech backbone and train only a small text-conditioning adapter. Compare it
against its exact initial checkpoint using development CER/WER and speaker
similarity, followed by listening. Freezing the backbone does not guarantee
voice preservation because text conditioning can still alter speech. Reject
pronunciation gains that sacrifice voice fidelity. Do not select this recipe
on the already inspected test set. The user subsequently authorized the
[targeted training pilot](0.6b-targeted-voice-training.md), which starts from
the exact halfway model and evaluates pronunciation and voice at each checkpoint.
