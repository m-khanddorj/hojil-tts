# Fresh-rollout direct voice pilot

This bounded experiment starts from audited unfiltered middle-attention update
4. Only its existing rank-4 Q/V LoRA in layers 10–17 (163,840 parameters) is
trained. Original acoustic weights, speaker adapter, codec and speaker encoder
stay frozen. The accepted global model is unchanged.

## Registered procedure

Four optimizer updates are permitted. Each uses 16 fresh recordings from the
current policy, cycling evenly across 36 fitting speakers. Training generation
uses the established CUDA FP32 talker / CPU codec path. Final evaluation remains
CPU FP32 SDPA, four threads, with unchanged sampling settings and both seeds.
Every fresh recording is ASR-scored. A truncated training rollout stops the
pilot instead of being silently dropped.

There is one hash-selected fixed anchor per fitting speaker: an old recording
with zero ASR CER, cosine in [0.96, 0.984), and at most 172 combined frames.
That length criterion selects old anchors only. Fresh audio uses native codec
chunk boundaries and activation checkpointing without truncation. No final
evaluation condition is shortened or removed.

Current acoustic-conditional probabilities are collected, the frozen codec
provides a straight-through speaker gradient, and a separate talker process
replays it into LoRA. Reference probabilities remain fixed one-hot constants.
Posterior replay and exact native hard-code forward values are checked. This
is a biased surrogate; actual generated speech remains the outcome measure.

## Pronunciation constraint

AdamW uses learning rate 2e-5, zero weight decay, FP32 moments and gradient
clipping at 1. Its proposed parameter update is projected to avoid a first-order
increase in mean token NLL on all 36 anchors. A projected steepest-voice direction
is used if necessary to retain voice descent. No common descent stops the run.

Up to eight step halvings are allowed. Acceptance requires actual anchor NLL
at most its previous value plus a 1e-6 FP32 tolerance, a negative predicted
voice-loss change using the actual rounded update, and at most 1% effective
LoRA displacement per matrix. Rejection restores the prior adapter and saves
no checkpoint. Adam starts fresh and retains moments across accepted updates.

Zero ASR CER is not human pronunciation certification, and token loss is not
CER. This constraint does not prove preserved pronunciation. Fixed validation
NLL covers all 62 zero-ASR-CER records from 16 preference-validation speakers,
excluded from this fitting. That diagnostic subset is distinct from the old
full DPO validation pool and does not replace generated-speech evaluation.

## Evaluation and observability

The starting checkpoint regenerates all 26 screen recordings with exact waveform
hash parity against the earlier model. Every accepted update then undergoes the
same complete synthesis, separate ASR scoring and independent audit. Original-
reference cosine, edit counts, aggregates, codecs/EOS and frozen state are checked.

Two consecutive speech-harm warnings stop fitting. A passing joint screen stops
for all 114 existing confirmation recordings. Both groups still require CER
strictly below 3% and cosine strictly above 0.984. There is no automatic promotion.

The report records CER, WER and cosine by group; anchor NLL before/after; fixed
validation NLL; gradient norms/alignment; backtracking; accepted step scale;
matrix movement and posterior replay error. Fresh training audio has separate
ASR/voice telemetry. Fixed-hard-trajectory speaker loss is constant as weights
change and is not presented as a learning or validation trend.

## Verification and status

Five objective tests pass, including checkpointed native chunking/gradient
equivalence and descent conditions. Two actual small-Qwen optimizer tests pass:
accepted updates preserve original weights and FP32 moments, while failed
backtracking restores the adapter and creates no checkpoint. The earlier real
0.6B gradient-replay proof is also required.

Source, runtime, tests, model/data provenance, confirmation panel and external
driver are pinned. Historical registered sources remain unchanged. Artifacts
are outside Git under direct-voice-pilot; status is
direct-voice-pipeline-status.json.

The starting checkpoint passed exact waveform parity on all 26 recordings and
independent score/provenance audit (cosine recomputation error zero):

| Group | CER | WER | Original-reference cosine |
|---|---:|---:|---:|
| Development | 2.0484% | 4.5977% | 0.9850573 |
| Custom reference | 1.6355% | 4.6875% | 0.9790958 |

Both pronunciation thresholds pass at initialization; the custom voice
threshold does not.

Update 1 passed the native optimizer checks at full step scale. Anchor NLL was
3.649726524 before and 3.649727018 after (+4.93e-7, within the registered 1e-6
tolerance). Validation NLL was 3.683837432, gradient replay error zero, and
voice/anchor gradient cosine -0.176906. Its complete speech screen and independent
audit subsequently passed, with these measured outcomes:

| Group, update 1 | CER | WER | Original-reference cosine |
|---|---:|---:|---:|
| Development | 2.7002% | 5.7471% | 0.9850205 |
| Custom reference | 0.9346% | 3.1250% | 0.9792840 |

Eleven of 26 waveforms changed. The custom mean improved, but development CER
worsened without a voice gain: one speech-harm warning under the registered
rule. Both CER thresholds still pass; custom cosine still fails.

The small custom improvement is uncertain: its exploratory paired-bootstrap
cosine-change interval is [-0.000833, +0.001355], including zero. These 10,000
draws retain both seeds within each of three custom-text blocks (or ten
development-speaker blocks). They are unadjusted for repeated selection and
do not replace the full confirmation panel.

Update 2 also passed its independent 26-recording audit, but failed the quality
objective. The driver stopped normally after two consecutive speech-harm warnings;
updates 3 and 4 were not attempted, and no confirmation or promotion occurred.

| Group, update 2 | CER | WER | Original-reference cosine |
|---|---:|---:|---:|
| Development | 4.1899% | 9.7701% | 0.9850176 |
| Custom reference | 0.9346% | 4.6875% | 0.9789247 |

Nineteen of 26 waveforms changed versus initialization. Development gained 23
character errors, including 12 on dev-003/seed-2027. No evaluation text is added
to fitting to repair this example. Development CER increased by 2.1415 percentage
points (exploratory paired interval +0.2757 to +4.8780 points). Custom cosine
fell below initialization, and neither update achieved the joint target.

Update 2's anchor NLL moved from 3.649727018 to 3.649727321, again inside tolerance;
validation NLL was 3.683849019. Both gradient replays were exact. The small token-
loss changes did not preserve generated pronunciation. This is evidence against
the present surrogate/constraint, not proof of ordinary validation-loss overfit.
The second codec batch completed in 0.64–1.59 seconds per recording without the
first batch's runtime outlier.

All 16 native codec gradients passed exact hard-waveform checks. Peak allocated
memory was 3.51 GiB. One 164-frame case took 342.89 seconds, while the others
took 0.73–2.08 seconds. Process inspection found only this training process and
the Windows desktop using the GPU. Near-full GPU memory was observed during
the slow case, but allocator reservation, driver workspace and paging have not
been separated; the cause is not yet established. The batch completed normally.

A separate read-only artifact, `direct-voice-observability.html`, plots audited
CER/WER/cosine, fixed fitting/validation NLL and gradient alignment. It also
reports waveform changes, replay error, accepted scale and codec runtime/memory.
Its script rechecks audit summaries and all evaluated waveform hashes. Completed
codec profiles are explicitly distinguished from audited speech outcomes.
