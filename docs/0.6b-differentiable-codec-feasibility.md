# Differentiable codec feasibility

This is a separate, read-only feasibility investigation prompted by the failed
preference fits. It does not change the current residual-temperature experiment,
the accepted model, the scoring definition or the joint goal.

## Literature and applicability

[DiffRO](https://arxiv.org/html/2507.05911v1) replaces discrete sampling with a
Gumbel-Softmax surrogate and uses a trained token-to-reward model. On its
CosyVoice2 SFT model, English WER improves from 4.26% to 2.57% with ASR rewards,
versus 3.28% for DPO. The reward model uses over 13,000 hours of labeled or
pseudo-labeled audio; it is not a ready-made Qwen/Mongolian component. The
paper also reports discrepancies between token-predicted and decoded-audio
attributes. A direct path through our existing codec and speaker encoder is
therefore an architectural hypothesis, not a DiffRO reproduction.

[RRPO](https://arxiv.org/html/2512.04552v1) documents acoustic artifacts that
raise a differentiable emotion reward while reducing perceived quality. Its
robust reward-model training uses smoothing, mixup and adversarial examples.
This argues against treating a larger internal cosine as sufficient evidence
of perceptual improvement. Generated speech, pronunciation checks and listening
remain necessary; the existing numerical goal is unchanged.

[CSP-FT](https://arxiv.org/html/2501.14273v2) learns layer importance using
speaker/emotion recognition before selecting the highest- and lowest-weight
layers for adaptation. Its preparatory analysis uses 244 hours and 75 epochs;
it does not establish universal Qwen speaker layers or justify arbitrary
weight-space projections. It is an alternative localization method, not the
method implemented here.

## Implemented component

`training/differentiable_codec_probe.py` maps codebook probabilities to the
frozen Qwen codec's existing embeddings and projections. It uses the exact
hard-code latent in the forward pass, adding a zero-valued expression that
carries the soft-latent gradient in the backward pass. This straight-through
gradient is biased and local to a fixed trajectory; it does not differentiate
the real discrete autoregressive sampler.

Three CPU tests with a tiny instance of the actual 16-codebook Qwen decoder
pass. They check native forward equality, one-hot codebook equivalence, the
surrogate gradient against an independently composed latent vector-Jacobian
product, finite nonzero gradients, and rejection of invalid coverage/codes or
a trainable codec. No full model or GPU is used by these tests. These checks
establish component correctness, not training usefulness or improved speech.

## Prepared native probe

The external `probe-native-codec-gradient.py` will, only after the current
calibration exits and fails its expansion gate, inspect one hash-selected
preference-fitting trajectory. Selection uses frame length and termination,
not its voice or ASR score. The original complete batch is reconstructed for
exact native CPU WAV parity, preserving padding, chunking and reference trimming.

Only the existing codec decoder and original speaker encoder are loaded.
The probe then checks exact hard-forward equality on GPU and a finite nonzero
speaker-loss gradient with respect to synthetic soft-code logits. It measures
GPU memory and time, verifies frozen weights, and performs no optimizer step,
code update, fitting or new speech selection. Synthetic probabilities are a
connectivity probe, not actual TTS posteriors. This cannot meet the goal.

## Native probe result

The residual-temperature calibration failed its registered expansion gate and
its original process exited successfully. The native probe then ran separately
and completed successfully on fitting trajectory `balanced-114-draw-1`
(92 generated frames, 7.36 seconds). No model job remains running from these
two experiments.

- Reconstructing the original four-draw batch exactly reproduced the stored
  PCM WAV SHA-256 `9add04d3c1578e4b958092edfcc271e36a7aa0056d7a5f3cbcc89236bce63c9c`.
- Re-extracted native PCM cosine was 0.9858881235 versus recorded 0.9858880639
  (difference 5.96e-8).
- The straight-through waveform exactly matched native hard decoding on GPU.
  The generated-code logit gradient norm was 0.0005054121, finite and nonzero.
  Codec and speaker-encoder weights remained unchanged and accumulated no
  parameter gradients.
- Peak GPU allocation was 6,875,452,416 bytes (6.40 GiB). The GPU probe took
  2.24 seconds, excluding model loading and CPU reconstruction.

The GPU floating-waveform loss was 0.01433873. Its value must not be compared
as an improvement against the stored CPU/batched/PCM score: those are distinct
numerical paths. The development/custom evaluator remains unchanged. Reference
code logits also have a nonzero mathematical sensitivity in this diagnostic;
they must stay constant when connecting generated-code gradients to the policy.

The output is `native-codec-gradient-probe/results.json` outside Git, with a
registration that pins the probe, bridge, tests, selected training data and
model sources. This proves connectivity and native forward equivalence only.
No code, model parameter or audio was optimized.

Next, actual policy probabilities must replace the synthetic probabilities.
The memory measurement motivated separate frozen-policy collection, codec
gradient computation, and exact policy replay, without simultaneous codec and
talker graphs. That [integration now passes a native read-only check](0.6b-codec-policy-replay.md),
including unchanged parameters between passes and exact posterior replay.
No fitting has occurred. Surrogate bias and the gap between speaker-encoder
reward and perceived voice remain unresolved.
