# Historical merge precision diagnostic

November 11, 2026. This is a read-only weight-space measurement, not a changed
training run or an observed speech-quality gain.

`training/evaluate.py` deliberately preserves the historical BF16 export
policy: load the base in BF16, load the selected FP32 LoRA adapter, cast the
talker and adapters to BF16, then merge. The training masters remain FP32,
but inference uses the rounded exported weights even when later loaded in
FP32. Casting the export back to FP32 cannot recover discarded update values.

The diagnostic verified the original base, selected epoch-2 adapter and merged
model hashes, then compared every one of the 233 adapted matrices:

| Component | Matrices | Relative update error | Update-direction cosine | Nonzero update elements rounded to zero |
| --- | ---: | ---: | ---: | ---: |
| All adapted matrices | 233 | 12.52% | 0.992242 | 20.15% |
| Main decoder | 196 | 12.51% | 0.992255 | 20.97% |
| Text projection | 2 | 11.01% | 0.993988 | 16.68% |
| Residual predictor | 35 | 12.98% | 0.991671 | 15.84% |

Here the intended update is `B_fp32 @ A_fp32` (alpha/rank = 1); the exported
update is the saved BF16 merged matrix minus the original base. Relative error
is the Frobenius norm of their difference divided by the intended update norm.
The intended aggregate norm is 5.123180 and the difference norm is 0.641372.
This percentage refers to the **small LoRA update**, not to total model weights,
speech quality, or a fraction of training that was lost. Entries rounded to
zero include small updates; their count is not their share of the update norm.

Replaying the installed PEFT CPU BF16 merge reproduced every exported element
exactly: zero mismatches across 525,336,576 adapted-matrix elements. This ties
the numerical difference to the recorded export policy rather than a guessed
checkpoint mismatch. The original FP32 adapter is preserved.

The result warrants a separate, controlled FP32 merge comparison using the
same base, adapter, coefficient, texts, seeds and decoding. It does not prove
that higher precision improves CER or voice. In particular, the accepted
halfway model is a blend of two exported endpoints; it is not exactly a
half-strength application of the original FP32 LoRA update. A comparison must
name those constructions distinctly and retain all generated outputs.

No historical module, checkpoint or registered preference experiment was
modified. Artifact details and per-matrix statistics are in the external
`merge-precision-diagnostic.json`, produced by `inspect-merge-precision.py`.

## Registered inference comparison

`training/fp32_merge_comparison.py` registers one candidate: the original base
in FP32 plus half of the original FP32 epoch-2 LoRA update. Compare it against
the accepted halfway endpoint blend on all 13 fixed cases and both seeds,
with the same CPU FP32 SDPA generation, pinned ASR and original-reference
cosine. No optimizer is involved and no candidate is promoted automatically.

Before candidate synthesis, reconstruct the historical halfway construction
and require byte-identical control audio for custom-001 at seed 2026. Focused
tests verify preservation of small updates erased by BF16, correct functional
scaling, untouched unrelated parameters, exact zero-strength behavior and
rejection of invalid or low-precision adapters. CPU generation and GPU ASR
are separate phases; scoring must wait for the active preference pipeline's
GPU work. Run artifacts live outside Git in `exact-fp32-half-merge/`.

The legacy control passed: reconstructed custom-001 at seed 2026 is
byte-identical to the accepted halfway waveform. Candidate generation completed
the fixed 26-recording panel with zero truncations. The independent audit is implemented externally in
`verify-fp32-merge-comparison.py`: it checks all model tensors against the
base plus original FP32 adapter, verifies audio provenance, re-extracts
original-reference cosines and recomputes stored ASR edit counts. It does not
rerun ASR inference.

The generation-only audit passed all 26 recordings and every model tensor,
including all 233 adapted matrices and unchanged unrelated parameters.
Re-extracted cosines match exactly: development macro cosine 0.987000546,
custom 0.984753311. Both clear the absolute voice threshold. The accepted
halfway values were 0.986513475 and 0.984960198, respectively, so the custom
mean decreased slightly.

The first audit attempt used two CPU threads and did not reproduce the model
hash. Reconstructing the FP32 matrix products with the registered four-thread
setting reproduced the exact model and passed the independent tensor checks.
The auditor now uses four threads; it did not change any candidate weight or
audio artifact. FP32 merge construction must retain this backend setting, not
only the generation thread count.

After the preference pipeline exited, ASR scoring and the full independent
audit completed successfully. Development CER/WER is 10.71%/29.31%, versus
9.31%/23.56% for the accepted halfway blend. Custom CER/WER is 7.48%/18.75%,
versus 7.24%/23.44%. Thus CER worsened in both groups despite improved custom
WER and development mean voice similarity. Both absolute voice thresholds
pass; neither CER threshold does. The candidate is rejected as a replacement.
No optimizer, historical checkpoint, selection pointer or accepted audio was
changed. This experiment shows that eliminating merge rounding does not by
itself improve this model's generated speech under the fixed protocol.
