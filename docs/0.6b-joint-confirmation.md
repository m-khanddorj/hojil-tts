# Expanded joint-goal confirmation

The goal requires CER strictly below 3% and original-reference internal
speaker cosine strictly above 0.984 in **both** groups. The existing external
`joint-goal-confirmation/protocol.json` registered 44 development targets and
13 custom-reference texts at two fixed seeds: 88 + 26 = 114 recordings. It
predates preference outcomes. This expands development/personalization checks;
it is not an untouched test set.

The reference-specific profile experiment has a separate prepared runner,
`training/reference_profile_confirmation.py`, because its registered historical
evaluators remain immutable. It requires a completed, independently audited
mean-follow-up screen pass, freezes the selected profile and shared model, and
preserves the full 114-case scope. All 26 screening waveforms must reproduce
exactly in confirmation. Three focused tests cover strict entry thresholds,
complete coverage, truncation, extra case metadata and waveform parity. No
native profile confirmation has run: its completed screening result failed the
custom-reference CER and cosine requirements.

The subsequent profile-DPO pilot has its own prepared
`training/reference_profile_preference_confirmation.py` runner. It requires the
terminal registered DPO stopping decision, the complete 50-recording checkpoint
audit, and an actual strict two-group 26-recording screen pass. It then regenerates
the original 114 cases with all metadata retained and requires all 26 screening
waveforms to reproduce exactly. Four focused tests passed, including nonfinite
independent cosine rejection. No DPO checkpoint has qualified or entered native
confirmation yet.

Before registration, this DPO confirmation runner was also hardened to pin the
exact ASR download-manifest hash and reject changes before any phase performs
model work. Scoring still verifies each declared ASR file. The four-test suite
includes rejection of a changed manifest even when its revision string stays
the same. Current DPO training and evaluation registrations were not changed.

The later no-training PAD experiment has its own prepared
`training/reference_prefix_generation_pad_confirmation.py` runner. Its four
CPU tests and independent review passed. It requires a terminal audited
full-PAD screen pass, inherits the parent's exact ASR manifest, and verifies
the expanded panel against its historically registered hash, including the
unscreened case metadata. It retains all 114 recordings and requires all 26
screening WAVs, scores and native codec trajectories to reproduce. The PAD
screen passed: development CER 1.6760%, cosine 0.984636086; custom CER 2.8037%,
cosine 0.984976113. After its original process closed successfully, the separate
confirmation driver completed all 114 recordings and the native independent
audit. The original process exited successfully, but quality confirmation failed:

| Group | Recordings | CER | WER | Original-reference cosine |
| --- | ---: | ---: | ---: | ---: |
| Development | 88 | 4.2226% | 10.7306% | 0.984226523 |
| Supplied reference | 26 | 3.2796% | 8.2707% | 0.983555874 |

All recordings terminated, frozen weights were unchanged, all 26 screen WAVs,
scores and codec trajectories reproduced, and all independently recomputed
cosines were finite with zero discrepancy. A separate standard-library audit
also verified the historical panel, all 114 artifact identities and independent
ASR edit counts. Its receipt is `prefix-pad-goal-audit.json` in the external
artifact root, with `goal_criteria_met: false`. No model was promoted and the
goal remains active. The 26-recording screen was insufficient to establish the
quality of the broader development/personalization panel.

All 88 development references bypass this candidate's custom-reference routing
and PAD intervention. Their result measures the centered-step-16 fallback;
changing only the custom-reference branch cannot fix this development failure.
The next comparison will evaluate a different existing acoustic adapter with
the reference-conditioning intervention on all 114 recordings from the outset.

`training/confirm_joint_candidate.py` now executes that panel for either the
bounded speaker-preference adapter or the FP32 half-merge comparison. It
accepts only a complete, independently audited 26-recording screening pass.
Preparation pins the candidate checkpoint, screening results/audit, panel,
source code and original experiment provenance. Existing registered modules
and experiments remain unchanged.

Run the separate phases `prepare`, `generate`, `score`, `audit` with
`python -m training.confirm_joint_candidate --output <external-directory>`.
Preparation also requires `--kind speaker --candidate <source-run> --step N
--panel <registered-panel-json>`; precision candidates use `--kind precision`
without a step. Refreshed speaker-preference stages use `--kind refreshed`
with their additional-update number. No passing candidate is available yet, so no confirmation run
has been prepared or launched.

Centered speaker-residual candidates use `--kind centered`. Loading verifies
both the frozen acoustic weights and the unchanged original adapter/PCA
components; generation also checks that these components and the trainable
residual remain unchanged. Five focused tests now pass, adding a centered
candidate restoration/tamper check to the original four scope/threshold tests.

Reference-prefix routing candidates use `--kind prefix`. Preparation requires
the complete matrix/codec/routing audit as well as a joint screen pass. The
confirmation checks alternate-matrix and speaker-adapter identity, unchanged
weights during generation, and reference/target routing spans on all cases.
Six focused confirmation tests pass, including rejection of a changed set of
alternate reference matrices. The required 114 recordings and thresholds are
unchanged; no passing candidate has entered confirmation yet.

Reference-audio-only routing uses `--kind codec`, requiring the 196-matrix
audit and recorded exact full-text-prefix checks. All 114 confirmation cases
retain the per-generation hidden-state guard and receive routing-boundary
checks in the independent audit. The six focused tests also cover changed
alternate-matrix rejection for this variant.

Speaker plus reference-audio routing uses `--kind condition`. Its separate
196-matrix audit must verify the speaker position and the recorded exact
leading-control checks; it does not claim exact text hidden states. The same
six tests pass with this variant's alternate-matrix identity checks included.

Middle-attention LoRA uses `--kind attention` with the checkpoint step. Its
screen audit must verify the 16 intended projections and frozen original
speaker adapter. Confirmation restores the LoRA and checks canonical acoustic
identity, the speaker-state hash and unchanged trainable tensors throughout
generation. Seven focused tests pass, including rejection of a changed frozen
speaker adapter. The panel and thresholds remain unchanged.

Absolute-quality preference fits use `--kind quality`. They use the same LoRA
restoration and original-speaker identity guards, plus required screening audit
coverage for the actual fitting subset, full unfiltered validation and fixed-
probe telemetry. Eight focused tests now pass, including the quality candidate's
frozen-speaker tampering check. This adds a candidate type, not a change to the
114 recordings, thresholds or promotion rules. No quality-fit candidate has
yet qualified for confirmation.

Generation uses the same CPU FP32 SDPA settings and original audio/text
conditioning, resetting the fixed seed for every case. It regenerates all
114 recordings and requires the original 26 screening waveforms to reproduce
exactly. Frozen acoustic weights and any speaker adapter must remain
unchanged. No favorable seed or best-of-N selection is allowed.

GPU ASR is a separate phase and must wait until other training/ASR processes
have exited. It uses the pinned Mongolian recognizer and decoding settings.
The final audit reloads the candidate, checks audio/reference hashes,
re-extracts every original-reference cosine, recomputes edit counts from the
stored ASR hypotheses, and verifies both aggregates and all 114 cases. It does
not rerun ASR inference. Neither a scored nor audited pass automatically
changes model selection or marks the broader thread goal complete.

Four focused tests cover complete two-group measurement, strict boundaries,
missing or duplicate recordings, favorable-seed subsets, altered references,
truncation, and attempts to weaken the registered scope. The real audited
update-8 candidate was also rejected before any output directory was created,
because its development CER and custom cosine do not pass. This verifies the
entry gate; it does not establish a successful full confirmation execution.
