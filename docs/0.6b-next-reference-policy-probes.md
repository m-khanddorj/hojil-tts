# Conditional probes after reference-profile DPO

The profile-DPO pilot finished normally at step 16 without meeting the goal:
custom CER 3.9720%, cosine 0.981111487. Voice similarity reversed from step 8,
and reserved CER reached 8.7037%. Its original process closed before the
separate PAD-ablation driver launched. PAD registration and all 26 native
historical controls have passed. The full-PAD intervention passed both groups
on the complete 26-recording screen. Its original process closed successfully,
and the separate 114-recording confirmation has registered and begun generating.
The full goal remains unproven. Other probes below remain proposals.

## Refresh trajectories before attributing failure to capacity

The current 1,024-parameter profile fits most collected pair rankings, but only
eight of 64 recordings across seven of 16 training texts pass both absolute
targets. This does not establish that the profile has enough capacity, nor that
the data support the desired generated-speech behavior. At checkpoint 4 the
1% input-displacement cap is inactive (actual movement 0.317181%).

If generated speech fails, one controlled option is to fork checkpoint 4 with
its optimizer state, generate four new fixed-seed alternatives for each of the
same 16 training texts, and run four otherwise identical preference updates.
The comparator is the existing checkpoint 8 trained on the original pool.
Keep the zero-profile reference policy, pair rule, equal-text weighting,
parameterization and evaluation fixed. Measure absolute joint support before
training, and specify treatment of texts with no valid pairs before collection.
This tests refreshed trajectory supervision; it does not isolate parameter
capacity or prove that four draws reveal the attainable quality ceiling.

generated-frame conditioning is full-weight. Earlier codec-only routing used
full PAD but also changed the prefill; it did not isolate this variable.

A separate prepared experiment will retain the old half reference/control
prefill and replace only `trailing_text_hidden` and `tts_pad_embed` at the native

arguments must change because the first cached decode uses the trailing text
and subsequent steps use PAD. Prefill inputs, masks and the first frame's 16
codec IDs must remain exact. Custom-reference dispatch controls both routing
and the PAD intervention; all other references retain centered-step-16 behavior.

all 20 centered development recordings. The intervention then receives its own

### Training replay if needed

The existing router is CPU inference-only and activates through `generate`.
Attaching it directly to the current teacher-forced trainer would score a
different policy. Any training implementation needs an explicit matching
reference/target row mask, native prefill and decode parity, likelihood replay
checks, and gradients confined to the registered adaptation parameters.

The completed DPO result led to the PAD ablation; later choices depend on its result.
A larger displacement bound and a larger parameterization are distinct
hypotheses and should not be changed together with the data or starting policy.
